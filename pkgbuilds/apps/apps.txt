# The application suite, as tools/gen-app-pkgbuilds-local.sh builds it from
# local working trees for ISO testing.
#
# Format: name|pkgdesc|extra depends (space separated)|extra optdepends (comma separated)|released package name
#
# The last field is needed only where the released package is not named after
# the repository: peek ships as magnetar-peek, because every distribution
# already has an unrelated `peek` (a GIF recorder).
#
# Nothing here ships. Every app releases through linux-release-kit, which
# publishes a versioned package to [magnetar]; the ISO and the installer name
# those packages. The local -git builds provide the same names, so an ISO built
# against build/repo resolves them the same way.
#
# locket is deliberately absent. It already has a hand-written PKGBUILD at
# locket/packaging/arch/PKGBUILD with a dependency list derived from what its
# binaries actually link against, plus a post-install that explains taking over
# org.freedesktop.secrets. Regenerating a worse one here would be duplication.
#
# Dependencies: the generator emits the libcosmic base set derived from what
# installed COSMIC applications actually link (glib2, libxkbcommon,
# systemd-libs, zlib). Anything beyond that is per-app and must come from
# namcap against a real build, not from reading the source. The released
# packages get theirs from linux-release-kit, which builds them.
